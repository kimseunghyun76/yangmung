# 4단계 — 사용자 페르소나 회귀 테스트

> `docs/usability/PERSONAS.md`에 정의된 8개 페르소나 중 사용자가 지정한 4명(1·2·3·7)으로, 1~3단계에서 두 전문가가 지적한 문제가 실제 사용자 과업에도 영향을 주는지 검증했다. 페르소나 1·7의 핵심 과업은 1단계 UX 감사에서 이미 실행 확인한 내용을 그대로 인용하고, 페르소나 2·3은 이번 단계에서 별도로 실행/코드 검증했다.

- 테스트 환경: 1단계와 동일(커밋 `a0b78a8`, `npm run dev`, Claude Browser 프리뷰).

## 페르소나 1 — 가나도 모르는 첫 일본 여행자

핵심 과업: 완전 초보자 과정 찾기 → 한글 발음 보조 활성화 확인 → 편의점 봉투 요청 → 식당 주문 → 호텔 체크인 → 다음 날 복습.

- **완전 초보자 과정 찾기**: 성공. 신규 계정으로 수준 진단을 전부 "모르겠어요" 처리하면(`[실행 확인]`, 1단계 §2) 정확히 "입문"으로 배정되고 `readingAid: 'always'`(항상 보조)로 설정된다(`recommend()` 함수, `read<0.4·listen<0.4·situation<0.4` → beginner 분기, `[코드 확인]`).
- **한글 발음 보조 활성화 확인**: 부분 성공 — 정확히는 "한글 발음(음역)"이 아니라 "일본어+한글 **뜻**"(`choiceMode: kana_ko`)과 "로마자 보조"(`readingAid: always`)가 켜진다. 학습 전문가 감사(§9)가 지적했듯 phrase 단위의 한글 음역 표시는 애초에 존재하지 않으므로, 이 과업은 "앱이 제공하는 형태의 보조"로는 성공하지만 페르소나가 기대했을 수 있는 정확한 형태(가나 옆 한글 발음)와는 다르다.
- **편의점 봉투 요청 / 식당 주문 / 호�텔 체크인**: 이 세 과업은 전부 **여행 미션**(C1·C2 등)에 속하는데, 입문 단계에서는 미션 자체가 잠겨 있어 **접근 불가능**(`[실행 확인]`, 1단계). 즉, 이 페르소나가 진단 결과 그대로(입문) 진행한다면 이 세 과업 중 어느 것도 즉시 수행할 수 없고, 먼저 입문·기본 레벨의 가나·어휘 학습을 상당량 마쳐야 한다. 이는 교차 검토 §1(입문→중급 이진 전환)이 실제 과업에 미치는 영향을 그대로 보여주는 사례다 — **전문가가 지적한 구조적 문제가 이 페르소나의 핵심 과업 3개를 직접 막는다.**
  - 단, 긴급 화면(`Emergency.tsx`)에 한해서는 레벨과 무관하게 "미아 찾기"류 상황을 바로 연습할 수 있다는 예외가 있다(1단계 §2 강점).
- **다음 날 복습**: 성공. 복습장이 학습한 가나·표현을 정확히 반영하고(1단계 §2), 새로고침 후에도 상태가 유지된다(1단계 실행 확인).
- **모바일에서 설정 접근**: P0-1(내비게이션 바 모바일 잘림)이 실제로 이 페르소나에게도 영향을 준다 — 발음 보조를 끄거나 레벨을 수동으로 바꾸려면 설정 화면이 필요한데, 375px 폭에서는 그 버튼 자체가 화면 밖에 있다(1단계 §3).
- **중간 포기 가능성 평가**: 편의점·식당·호텔이라는, 페르소나가 원래 기대한 "여행 실전 회화"에 며칠 이상 도달하지 못하는 구조는 중도 이탈 위험 요인으로 판단된다(`[추론]`).

## 페르소나 2 — 여행 5일 전 벼락치기 사용자

핵심 과업: 출국까지 남은 기간 설정 → 5일 학습 과정 찾기 → 식당·교통·호텔만 선택 학습 → 여행 당일 필요한 문장 빠르게 검색 → 비핵심 콘텐츠 건너뛰기.

- **출국까지 남은 기간 설정**: 성공. 설정 화면에 "출국일" 입력란이 실제로 존재함을 확인했다(`[실행 확인]`: "설정하면 홈 화면에 출국까지 남은 일수(D-day)를 보여줘요").
- **"5일 학습 과정"**: 이런 이름의 전용 커리큘럼은 없다. 대신 D-day가 임박(14일 이내)하면 "첫 여행 생존"·"문제 해결" 카테고리가 **자동으로 우선 노출**되도록 미션 지도가 조정된다는 것을 이번 세션 초반 작업에서 직접 구현·확인했다(`[실행 확인]`: 미션 지도 상단에 "출국이 임박해 생존 표현부터 우선 열리도록 자동으로 맞췄어요" 문구). 다만 이 자동 우선순위는 **미션(중급 이상)에만 적용되고, 입문·기본의 가나·어휘 학습 자체를 건너뛰게 해주지는 않는다.**
- **핵심 발견 — 설정에서 수동으로 레벨을 올려 미션에 즉시 도달 가능**: 신규 계정 상태에서 진단을 건너뛰고 설정 화면에서 "중급"을 직접 선택하면, 즉시 "중급 레벨을 시작해요" 안내와 함께 편의점 미션이 그 자리에서 열리는 것을 확인했다(`[실행 확인]`). 즉 **가나를 모르더라도 강제로 여행 미션에 진입하는 경로 자체는 존재한다** — 벼락치기 사용자에게는 이것이 사실상의 "5일 벼락치기 모드" 역할을 할 수 있다. 다만 이 경로가 UI 어디에도 "급하신가요? 미션으로 바로 가기" 같은 형태로 안내되지 않고, 설정 화면 깊숙이 묻혀 있어(게다가 P0-1로 모바일에서 그 화면 자체에 도달하기 더 어렵다) **존재하지만 발견하기 어려운 기능**이다.
- **비핵심 콘텐츠 건너뛰기**: 우선 학습 카테고리(예: "먹고 즐기기"만 선택)는 이번 세션에서 신설한 즉시반영 로직으로 실제 작동을 확인했다(`[실행 확인]`, 이전 작업 세션). 다만 "이동과 관광"·"숙박과 생활" 등 카테고리 밖 콘텐츠를 **완전히 숨기는** 것이 아니라 "우선순위만 조정"하는 방식이라, 페르소나가 기대한 "교통·호텔만" 같은 엄격한 필터링과는 차이가 있다.
- **결론**: D-day와 우선 카테고리 자동화라는 절반의 답은 이미 있으나, "완전 초보자가 5일 안에 미션까지 도달"하는 유일한 실제 경로(설정에서 수동 레벨 상향)가 발견성이 매우 낮다는 점에서 교차 검토 §1과 다시 만난다.

## 페르소나 3 — 귀는 트였지만 읽지 못하는 사용자

핵심 과업: 듣기/읽기 수준 분리 진단 → 기초 표현 건너뛰기 → 편의점 직원 질문 듣기 → 비슷하게 들리는 표현 구분 → 가나+발음 보조 동시 사용.

- **듣기/읽기 분리 진단**: 성공, 그것도 구조적으로 잘 설계되어 있다. 수준 진단이 애초에 읽기(6문)·듣기(5문)·상황(5문) 3축으로 완전히 분리 채점된다(`[콘텐츠 확인]`, `placementCards.ts`).
- **완전 초보로 오분류되지 않는가 — 직접 실행 검증**: `src/views/Placement.tsx`의 `recommend()` 함수를 이 페르소나의 실제 프로필(읽기 17%·듣기 80%·상황 40%)로 **직접 실행**한 결과, 다음과 같은 전용 결과를 반환하는 것을 확인했다(`[실행 확인]` — 코드를 통해 실제 함수를 호출).

  ```json
  {
    "mode": "express",
    "readingAid": "auto",
    "profile": "귀가 먼저 트인 여행자",
    "badge": "🎧",
    "title": "중급 (읽기 보조 켬)",
    "desc": "애니·드라마로 귀가 트인 타입! 듣기·말하기는 빠르게, 가나 읽기는 보조와 함께 따라잡아요."
  }
  ```

  즉 이 앱은 **정확히 이 페르소나를 위한 전용 분기**(`listenStrong && readWeak`)를 이미 갖추고 있다 — 완전 초보(입문)로 뭉뚱그리지 않고 "중급 모드 + 읽기 보조는 켜둠"이라는, 딱 맞는 절충 조합을 자동으로 추천한다. 이는 이번 회귀 테스트에서 확인된 **가장 견고한 기존 강점**이다.
- **기초 표현 건너뛰기**: 위 추천이 적용되면 `mode: 'express'`(중급)로 바로 배정되어 입문·기본의 가나 학습 단계를 거치지 않고 장면 미션으로 직행한다 — 과업 성공.
- **편의점 직원 질문 듣기 / 비슷하게 들리는 표현 구분**: 중급 모드의 "발음 구분"(비슷한 소리 변별) 스테이지가 레벨 진도 1번으로 배정되는 것을 확인했다(설정 화면 캡처, `[실행 확인]`) — 과업과 정확히 부합.
- **가나+발음 보조 동시 사용**: `readingAid: 'auto'`가 함께 적용되므로 가나 읽기 보조(로마자, 안 익숙한 글자만)가 유지된 채 장면 학습이 시작된다 — 과업 성공.
- **결론**: 이 페르소나는 4명 중 **가장 잘 대응되는 케이스**로 확인됐다. 전문가 지적 중 이 페르소나의 핵심 과업을 막는 항목은 발견되지 않았다.

## 페르소나 7 — 스마트폰에 익숙하지 않은 중장년 사용자

핵심 과업: 별도 설명 없이 첫 학습 시작 → 음성 재생 → 음성 속도 조절 → 학습 종료 후 재시작 → 복습 화면 찾기 → 여행 현장 문장 찾기.

- **별도 설명 없이 첫 학습 시작**: 1단계에서 확인한 환영 모달·수준 진단·결과 화면의 톤과 단순성(`[실행 확인]`, 1단계 §1·§2)은 이 페르소나에게도 우호적이다.
- **음성 재생**: 세션 카드 하단 "문장을 탭하면 다시 들을 수 있어요" 안내(1단계 §2)는 긍정적이나, **가나 상세 카드(KanaDetail)에는 재생 버튼이 없어 자동재생 1회를 놓치면 다시 들을 방법이 마땅치 않다**(1단계 §4-B, `[코드 확인]`) — 반응 속도가 느릴 수 있는 이 사용자군에게 특히 불리하게 작용할 조합이다.
- **음성 속도 조절**: 설정 화면에 "듣기 속도"(×0.5~×2, 누르면 바로 미리 듣기)가 존재함을 이번 단계에서 직접 확인했다(`[실행 확인]`). 다만 **P0-1로 인해 모바일 좁은 화면에서는 설정 화면 진입 버튼 자체가 화면 밖에 있어 이 기능에 도달할 수 없다** — 전문가가 지적한 구조적 결함이 이 페르소나의 핵심 과업 하나를 정확히, 직접적으로 차단하는 가장 뚜렷한 사례다.
- **학습 종료 후 재시작**: 1단계에서 세션 중도 "나가기"(확인 없이 즉시 종료, §4-E)와 브라우저 재진입(정상 복귀, §2)을 모두 확인했다. 확인 절차 부재는 이 페르소나에게 실수 위험으로 작용할 수 있으나 데이터 손실로 이어지지는 않는다.
- **복습 화면 찾기 / 여행 현장 문장 찾기**: 상단 내비게이션의 "복습" 탭 자체는 375px 폭에서도 화면 안에 남아 있어(1단계 §3의 측정값 기준 "복습" 버튼은 126~153px 구간으로 여전히 보임) 접근 가능하다. 다만 "여행 현장 문장 찾기"의 다음 동작인 "이 문장을 상대에게 보여주기"는 P1-1(문장 확대 기능 부재)로 인해 애초에 앱에 없는 기능이다 — 이 페르소나에게도 동일하게 영향을 준다.

## 종합 — 전문가 지적이 실제 과업에 미치는 영향 표

| 전문가 지적 | 영향받는 페르소나 | 실제 과업 차단 여부 |
|---|---|---|
| P0-1 내비게이션 바 모바일 잘림 | 1, 2, 7 | **예** — 설정 진입 필요한 과업(발음 보조 끄기·속도 조절·수동 레벨 상향) 전부 차단 |
| P1-1 문장 확대 기능 부재 | 1, 7 (여행 현장 과업 보유 시) | **예** — 기능 자체가 없어 해당 세부 과업 수행 불가 |
| 교차 검토 §1 (입문→중급 이진 전환) | 1, 2 | **예** — 편의점·식당·호텔 등 미션형 과업을 초반에 전혀 수행할 수 없음(단, 설정 수동 상향이라는 저발견성 우회로는 있음) |
| 가나 상세 모달 재생 버튼 없음 | 1, 7 | 부분적 — 과업 자체를 막지는 않으나 반복이 필요한 사용자에게 불리 |
| 페르소나 3 전용 진단 분기(`recommend()`) | 3 | **긍정적** — 오히려 이 페르소나의 핵심 과업을 정확히 지원 |

이로써 강도윤·한서연 두 전문가가 지적한 문제 중 다수(P0-1, 교차검토 §1, P1-1)가 **실제 페르소나 과업에 구체적으로, 반복적으로 걸린다**는 것이 확인됐다. 반대로 페르소나 3에서 보듯, 기존 설계 중 이미 잘 작동하는 부분(청각-우세 학습자 분기)은 그대로 유지해야 할 근거도 함께 확보했다.
