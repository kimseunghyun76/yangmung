# 전문가 의견 교차 검토

> `ux-expert-audit.md`(강도윤)와 `learning-expert-audit.md`(한서연)를 각각 읽고 교차 분류했다. 두 전문가의 판단을 서로 대체하지 않고, 겹치는 지점과 충돌하는 지점만 정리한다. 이 문서 자체도 아직 코드를 수정하지 않는다.

## 1. 두 전문가 모두 동의하는 문제 (우선순위 높음)

### 1-1. 입문→중급 전환이 점진적 곡선이 아니라 이진 스위치

- **강도윤(UX)**: 입문·기본 단계에서 "미션은 중급부터 열려요"로 여행 미션 전체가 차단되고, 그 결과 수집함(가챠) 화면에 54개의 잠금 카드가 그대로 노출되는 등 "이 시점에 무의미한 콘텐츠 과다 노출"이 발생한다(§4-D).
- **한서연(학습)**: `MODE_PRESETS` 쿼터를 보면 미션(장면 회화) 카드 배정이 입문 0개·기본 0개 → 중급 10개로 한 번에 뛴다. "문형·어휘 다지기"에서 "상황 회화"로의 전환이 점진적 곡선이 아니라 레벨업 시점의 이진 스위치다(§10).
- **판단**: 완전히 같은 구조적 원인(레벨 게이팅 로직)을 서로 다른 증상(UX: 화면에 잠금 카드 과다 노출 / 학습: 교육 곡선 단절)으로 각자 독립적으로 짚었다. 두 관점이 겹친다는 것 자체가 이 문제의 실재성을 뒷받침한다. **개선 백로그에서 최우선 후보로 올린다.**

## 2. UI/UX 전문가만 지적한 문제 — 학습 효과 훼손 여부 확인

| UX 지적 | 학습 효과에 해가 되는가? |
|---|---|
| P0-1 내비게이션 바 모바일 잘림 | 학습 콘텐츠 자체와 무관. 순수 기술적 결함이며 고치지 않을 이유가 없다. |
| P1-1 문장 확대해 보여주기 기능 부재 | 없음. 오히려 학습 목표(여행 현장 실사용)를 지원하는 방향이라 한서연의 "여행 과업 성공 우선" 철학과도 부합한다. |
| §4-A 히라가나 표 전체 선노출 | **주의 필요.** 오십음도 전체를 한눈에 보여주는 것은 전통적인 가나 학습법에서 공간적 위치 기억에 도움이 된다는 근거도 있어, 무조건 나쁘다고 볼 수는 없다. 강도윤의 "접어두기" 제안과 한서연의 "완성된 문장 틀 우선" 철학이 정면 충돌하지는 않지만, 전체 표를 없애는 방향보다는 접기/펼치기로 절충하는 편이 안전하다. |
| §4-B 가나 상세 모달 재생 버튼 없음 | 해가 되기는커녕 **학습 효과에도 긍정적** — 발음 반복 청취는 한서연의 "듣기와 말하기 연결" 항목과 직결된다. UX 개선이 곧 학습 개선인 사례. |
| §4-C 가나 퀴즈에 상황회화용 피드백 문구("이 상황에선 어색해요") 재사용 | 학습 내용 자체를 왜곡하지는 않으나(정답은 정확히 표시됨), 가나 읽기 문제에 "상황" 언급은 학습자에게 불필요한 혼란을 줄 수 있어 학습 관점에서도 수정 가치가 있다. |
| §4-E 세션 중도 이탈 시 확인 없음 | 학습 데이터(SRS 기록)는 이미 저장되므로 학습 효과 손실은 없음. 순수 오조작 방지 이슈. |

**결론: UX 전문가 단독 지적 중 학습 효과를 해치는 항목은 없다.** 오히려 §4-B는 학습 목표를 돕는 방향이라 이견 없이 진행 가능하다. §4-A만 "전체 삭제"가 아니라 "접어두기" 절충안으로 조정할 것을 권고한다.

## 3. 학습 전문가만 지적한 문제 — 화면 복잡도·구현 부담 확인

| 학습 지적 | 구현 부담 |
|---|---|
| §6 고급 문형 9개가 tier 미지정으로 조기 노출 위험 | **매우 낮음.** `GRAMMAR_LEVEL` 맵에 9개 항목의 숫자만 추가하면 되는 데이터 수정. 화면 변경 없음. |
| §4-B 〜てもいいですか 중복 항목 통합 | **낮음.** 중복 id 하나를 제거하고 참조를 정리하는 콘텐츠 정리 작업. 화면 영향 없음. |
| §2·§5 빠진 핵심 문형(も·たいです·が必要です·いる/ある 구분 등) 보강 | **낮음~중간.** 신규 문장 몇 개 작성 + 문법 팁 항목 추가는 기존 스키마 안에서 가능(신규 필드 불필요). 다만 원어민 검수가 필요해 콘텐츠 제작 리드타임이 있다. |
| §4-A "〜はどこですか" 등 기존 문장을 "문형" 단위로 묶어 보여주기 | **중간~높음.** 이 항목만 유일하게 **새로운 화면 개념**(문형 카드: 한국어 의도 → 일본어 틀 → 예문 그룹)이 필요하다. 기존 문장 재사용은 가능하나 UI·데이터 구조(문형 그룹 id) 신설이 필요해 강도윤의 "한 화면 하나의 목적" 원칙과 정면으로 만나는 지점이다 → §4 충돌 항목 참고. |

## 4. 서로 충돌하는 의견과 대안 검토

### 4-1. "문형 카드" 신설 여부

- **한서연**: 문형을 명시적으로 묶어 "이건 아까 배운 것과 같은 틀"이라는 설명이 필요하다(학습-구조 목록 §11, §12-1).
- **강도윤**: "한 화면에는 하나의 주목적", "긴 설명문·과도한 카드를 싫어함", "학습 콘텐츠와 UI 설명은 구분하되 UI 텍스트는 줄인다".
- 이 둘을 있는 그대로 합치면 "패턴 설명 화면을 새로 만들되 텍스트는 최소화하라"는 모순으로 보일 수 있다. **설명을 그대로 추가하는 대신 다음 조합을 검토한다.**
  - **예시 중심 설명**: 문형 규칙을 문장으로 풀어 설명하지 않고, 이미 배운 예문 2~3개를 나란히 보여주는 것만으로 "패턴"을 암묵적으로 느끼게 한다(예: "화장실은 어디예요?" / "역은 어디예요?" / "코인로커는 어디예요?"를 한 카드에 병렬 배치, 규칙 설명 문장 최소화).
  - **처음 한 번만 노출**: 그 문형에 속한 첫 문장을 배울 때만 "이 틀, 다른 데도 써요" 카드를 한 번 보여주고, 이후 같은 틀의 문장에는 작은 배지(예: 우측 상단에 "패턴" 태그)만 남긴다.
  - **도움말 버튼(선택적 확장)**: 기본은 예문 병렬 카드만 보이고, 더 알고 싶은 사용자만 "문법 자세히" 토글로 `grammar.ts`의 기존 `detail` 텍스트(이미 작성돼 있음, §8 재사용 근거)를 펼쳐 본다 — 신규 집필 불필요.
  - **사용 수준에 따른 선택 노출**: 입문·기본 레벨에서는 패턴 배지만, 중급 이상에서는 요청 시 문법 상세까지 — 이미 존재하는 `mode` 기반 레벨 분기 구조에 자연스럽게 얹을 수 있다.
- **결론**: "새 화면"이 아니라 "기존 카드에 얹는 얇은 레이어(배지 + 최초 1회 요약 + 선택적 상세)"로 절충하면 강도윤의 화면당 단일 목적 원칙을 깨지 않으면서 한서연의 패턴 인지 목표를 달성할 수 있다. 이 절충안을 개선 백로그의 "Aはどこですか 문형 그룹화" 항목 설계 조건으로 명시한다.

### 4-2. 히라가나 전체 표 노출 여부

- **한서연 관점(간접)**: 명시적으로 다루지 않았으나, "완성된 문장 틀을 먼저" 철학상 전체 표를 미리 보여주는 것 자체를 반대할 근거는 없다.
- **강도윤**: 화면당 단일 목적 위배(§4-A).
- **대안**: 완전 삭제가 아니라 **단계별 공개**(기본은 접힘 + "전체 표 보기" 토글) — 2번 항목의 대안 목록 중 하나만으로 해결되는 단순 케이스라 별도 실험 없이 바로 개선 후보로 등록 가능.

## 5. 실제 사용자 검증이 필요한 의견 (전문가 판단만으로 결정 불가)

- **한글 발음(음역) vs 로마자 중 어느 쪽이 한국어 화자에게 더 빠른 인지 경로인가**(학습 §9) — 두 전문가 중 누구의 취향 문제가 아니라 실증 데이터가 필요하다. A/B 테스트 후보.
- **세션 중도 이탈 확인 절차의 실제 필요성**(UX §4-E) — 오조작 빈도를 실측해야 확인 여부를 정할 수 있다.
- **문장 확대 기능의 실제 사용 빈도**(UX §3 P1-1) — 기능 부재는 확정적 사실이나, 신설 후 실제 여행 중 사용률은 사용자 관찰이 필요하다.
- **466개 표현 전체의 원어민 자연스러움 재검수**(학습 §7-C, §13) — 이는 사용자 검증이 아니라 원어민/교육 전문가 검증 대상으로, 한서연의 보고서에서도 명확히 별도 분류했다. 여기서는 "전문가 판단만으로 끝나지 않는 항목"이라는 점만 다시 확인한다.

## 6. 다음 단계로 넘기는 목록

- §1(입문→중급 전환 이진 스위치)과 §4-1(문형 카드) 두 항목은 서로 관련은 있지만 별개 백로그 항목으로 등록한다 — 전자는 "레벨 게이팅 완화/콘텐츠 노출 조정" 문제이고 후자는 "패턴 인지 UI" 문제로 해결 방법이 다르다.
- §3에서 구현 부담이 "매우 낮음"으로 분류된 항목(tier 데이터 수정, 중복 항목 통합)은 Quick Win 후보로 그대로 다음 단계에 전달한다.
