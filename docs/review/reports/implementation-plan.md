# 6단계 — 구현 계획 (Quick Win / Structural Improvement / Experiment)

> 아직 코드를 수정하지 않는다. 개선 백로그(`improvement-backlog.md`)의 항목을 세 묶음으로 분류하고, 각 항목이 어떤 전문가 지적과 어떤 사용자 실패(persona-validation.md)를 해결하는지 연결한다.

## Quick Win — 문구·간격·강조·노출 순서 등 작은 변경, 큰 효과

| 항목 | 해결하는 전문가 지적 | 해결하는 사용자 실패 |
|---|---|---|
| BL-05 고급 문형 9개 tier 지정 | 한서연 §6 | 입문·기본 학습자가 준비 안 된 상태에서 고급 문형(んです·そうです·ば조건 등)을 조기에 마주치는 상황 예방 |
| BL-07 가나 상세 모달 재생 버튼 추가 | 강도윤 §4-B | 페르소나 1·3·7 — 발음을 놓쳤을 때 다시 들을 방법이 없어 학습이 막히는 상황 |
| BL-09 가나 퀴즈 오답 피드백 문구 분기 | 강도윤 §4-C | 전체 학습자 — "상황"이라는 불필요한 언급으로 인한 혼란 |
| BL-10 〜てもいいですか 중복 문법 팁 통합 | 한서연 §4-B | 전체 학습자 — 같은 내용을 중복 학습하는 비효율 |
| BL-08 수집함 잠금 카드 레벨별 압축 | 강도윤 §4-D | 페르소나 1·7 — 아직 쓸 수 없는 콘텐츠 54개를 스크롤하며 느끼는 피로 |

이 5개는 기존 화면·데이터 구조를 유지한 채 조건 분기·데이터 값 수정만으로 완결되며, 서로 독립적이라 순서 상관없이 진행 가능하다.

## Structural Improvement — 내비게이션·학습 흐름·문형 데이터 구조 변경 필요

| 항목 | 해결하는 전문가 지적 | 해결하는 사용자 실패 |
|---|---|---|
| BL-01 내비게이션 바 모바일 오버플로 해결 | 강도윤 P0-1 | 페르소나 1(진단 재조정 불가)·2(수동 레벨 상향 불가)·7(속도 조절·설정 전반 불가) — persona-validation.md 종합표의 최다 영향 항목 |
| BL-02 문장 확대 오버레이 신설 | 강도윤 P1-1 | 페르소나 1·7 — 발화가 안 되는 상황에서 여행 현장 의사소통 수단 부재 |
| BL-03 입문→중급 전환 곡선 완화 | 강도윤+한서연(교차검토 §1) | 페르소나 1·2 — 편의점·식당·호텔 등 미션형 과업을 초반에 전혀 수행할 수 없음 |
| BL-04 "〜はどこですか" 등 문형 그룹화 레이어 | 한서연 §4-A, 교차검토 §4-1 | 전체 학습자 — 이미 반복 노출되는 문장의 패턴을 인지하지 못해 매번 새로 암기하는 비효율 |

이 4개는 화면 구조나 데이터 모델 변경이 필요해 Quick Win보다 설계 검토가 먼저 필요하다. BL-01은 다른 항목과 독립적으로 즉시 착수 가능(가장 심각도가 높고 구현도 명확함). BL-03과 BL-04는 서로 다른 화면(미션 게이팅 vs 세션 카드)이라 병행 가능하나, BL-04는 교차검토 §4-1에서 합의한 절충 UI(예시 병렬 카드 + 처음 1회 요약 + 배지 + 선택적 상세)를 설계 조건으로 반드시 따른다 — "설명을 그대로 추가"하는 방향으로 구현하면 강도윤의 화면 밀도 원칙과 다시 충돌하므로, 착수 전 이 절충안을 구현 명세로 확정한다.

## Experiment — 효과를 확신할 수 없어 실사용자 검증이 필요한 항목

| 항목 | 검증하려는 질문 | 관련 근거 |
|---|---|---|
| BL-02 문장 확대 기능의 실제 사용 빈도 | 신설 후 여행 현장에서 실제로 얼마나 쓰이는가 | 강도윤 P1-1, 교차검토 §5 |
| BL-03의 구체적 조기 개방 폭 | 입문·기본에서 미션을 몇 개까지, 어떤 조건으로 열어야 학습 순서를 해치지 않는가 | 교차검토 §1, persona-validation.md 페르소나 1·2 |
| BL-04 문형 그룹 노출 시 실제 패턴 인지 효과 | 배지·예시 병렬 카드만으로 사용자가 "패턴 재사용"을 체감하는가 | 한서연 §11, 교차검토 §4-1 |
| 한글 발음(음역) vs 로마자 — 어느 쪽이 더 빠른 인지 경로인가 | 문장 단위 읽기 보조를 로마자 대신 한글 음역으로 바꾸면 학습 속도가 개선되는가 | 한서연 §9, 교차검토 §5 |
| 세션 중도 이탈 확인 절차 필요성 | 실제 오조작으로 인한 세션 중단이 얼마나 빈번한가 | 강도윤 §4-E, 교차검토 §5(백로그에서는 제외, 여기서 재검토 대상으로만 유지) |

이 항목들은 백로그에 등록하지 않았거나(한글 발음 vs 로마자, 나가기 확인) 백로그 항목의 하위 질문(BL-02·03·04)으로, **구현 여부 자체보다 "어떻게 구현할지"에 대한 확신이 부족한 경우**다. Quick Win·Structural 항목을 먼저 구현해 데이터를 쌓은 뒤, 이 실험 목록을 실사용자 테스트 또는 사용 로그 분석으로 넘기는 것을 권장한다.

## 코드 수정 조건 충족 여부

사용자가 제시한 구현 조건(백로그 등록·우선순위 승인·검증 과업 정의·학습효과-가독성 충돌 해결)을 항목별로 점검한다.

| 항목 | 백로그 등록 | 검증 과업 정의 | 충돌 해결 | 우선순위 승인 |
|---|---|---|---|---|
| BL-01·05·07·08·09·10 | ✅ | ✅(각 항목 "검증 방법" 참고) | 해당 없음(충돌 없음) | **대기** |
| BL-02, BL-03, BL-04 | ✅ | ✅(단, 실사용자 검증은 별도 실험으로 분리) | BL-04는 교차검토 §4-1에서 해결됨 | **대기** |

**모든 항목이 마지막 조건인 "우선순위 승인"만 남아 있다.** 이는 이 문서만으로 결정할 수 없고 사용자(제품 책임자)의 승인이 필요하므로, 이번 6단계 산출물까지는 코드를 수정하지 않고 우선순위 승인을 기다린다.
