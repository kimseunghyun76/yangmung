## 1. 전체 UX 평가 요약

기본기(단일 화면-단일 목적, 색상 대비, 진단 결과의 명확성, 긴급 화면의 접근성)는 탄탄하다. 그러나 **모바일 우선을 표방하는 화면임에도 실제 좁은 모바일 폭(375px)에서 상단 내비게이션 바의 절반 가까운 메뉴(팁·가이드·설정)가 화면 밖으로 완전히 밀려나 조작 자체가 불가능한 치명적 결함**을 발견했다(§3, §4-A). 이 문제는 이번 세션까지 반복된 여러 차례의 사용성 테스트에서 한 번도 지적되지 않았는데, 지금까지의 테스트가 전부 데스크톱급 뷰포트(약 800~1280px)로 진행되어 왔기 때문으로 보인다. 또한 여행 현장에서 문장을 상대방에게 크게 보여주는 기능이 앱 전체에 전혀 존재하지 않는다(§3). 이 두 가지가 이번 감사의 핵심 발견이다.

## 2. 현재 앱의 강점

- **수준 진단 결과 화면**: "설레는 첫 여행자" 같은 닉네임, 0%라도 낙담시키지 않는 톤("처음이라도 괜찮아요!"), 3개의 구체적 다음 행동, "난이도는 설정에서 언제든 바꿀 수 있어요" 안내까지 — 완전 초보자를 정확히 식별하고 다음 행동을 명확히 제시한다. `[실행 확인]`
- **표현 검색(복습장 > 표현 탭)**: 아직 배우지 않은 표현을 검색하면 일본어 원문을 노출하지 않은 채 "OO 미션에 있어요 — 학습하면 여기 나타나요"로 안내한다. 학습 순서를 지키면서도 "검색했는데 아무것도 없다"는 막다른 경험을 피했다. `[실행 확인]`
- **긴급 화면 접근성**: 상단 내비게이션 바에 항상 노출되는 아이콘 1탭으로 도달하며, 전화번호는 `tel:` 링크로 즉시 연결되고, 레벨과 무관하게 미아·지진·병원 등 7개 상황을 바로 연습할 수 있다. `[실행 확인]`
- **퀴즈 정오답 피드백**: 오답은 빨간 테두리, 정답은 초록 체크로 즉시 대비되고, "이 상황에선 어색해요"류 설명이 함께 붙는다(단, §5-C에서 지적하듯 가나 읽기 문제에는 이 설명 방식이 어색하다). `[실행 확인]`
- **퀴즈 세션 안내 문구**: 화면 하단에 "문장을 탭하면 다시 들을 수 있어요"가 상시 노출되어, 반복 청취 기능이 존재한다는 것을 사용자가 굳이 찾지 않아도 알 수 있다. `[실행 확인]`
- **재진입**: 브라우저를 완전히 새로고침해도 홈 화면에 현재 레벨·다음 행동이 그대로 유지되고, 첫 진입 환영 팝업이 다시 뜨지 않는다. `[실행 확인]`

## 3. P0·P1 문제

### P0-1. 모바일 좁은 화면에서 내비게이션 바 3개 메뉴가 화면 밖으로 잘려 조작 불가능

- 발생 위치: `NavBar`(모든 허브 화면 공통 — 홈·학습·미션·복습·수집함·긴급·듣기 화면 전부에서 재사용됨)
- 증거 유형: `[실행 확인]` + `[코드 확인]`
- 실제로 발생한 일: 뷰포트를 375×812(아이폰 SE/6/7/8/X급 폭)로 맞추고 홈 화면을 열어 각 내비게이션 버튼의 실제 위치를 측정한 결과:

  | 버튼 | left | right |
  |---|---|---|
  | 홈 | 24 | 39 |
  | 학습 | 50 | 77 |
  | 미션 | 88 | 115 |
  | 복습 | 126 | 153 |
  | 수집함 | 164 | 203 |
  | 긴급 | 225 | 269 |
  | 듣기 | 280 | 324 |
  | 주야 | 335 | **379**(뷰포트 375 초과) |
  | 팁 | **390–434** | 화면 밖 |
  | 가이드 | **445–489** | 화면 밖 |
  | 설정 | **500–544** | 화면 밖 |

  `nav` 요소의 `scrollWidth`는 520px인데 실제 폭(`clientWidth`)은 327px뿐이고, `overflow-x: visible` · `flex-wrap: nowrap`이라 줄바꿈도 되지 않는다. `window.scrollTo(200, 0)`을 실행해도 `scrollX`가 0에서 움직이지 않아, 페이지 자체도 가로로 스크롤되지 않는다 — 즉 **터치·스와이프·스크롤 어떤 방법으로도 팁·가이드·설정 버튼에 도달할 수 없다.**
- 사용자가 기대할 행동: 좁은 화면에서도 모든 내비게이션 항목에 접근할 수 있어야 한다(꽉 찬 아이콘 압축, 가로 스크롤 처리, 또는 더보기 메뉴 등).
- 문제가 되는 이유: **설정 화면은 난이도 재조정·발음 보조(한글 표시) 토글·재생 속도 조절의 유일한 진입점이다.** 이 버튼에 닿을 수 없는 실기기 사용자는 사실상 이 기능들을 영구히 쓸 수 없다. 가이드·팁도 마찬가지로 완전히 닫힌다.
- 재현 단계: 375px 폭 뷰포트로 아무 허브 화면(홈 등) 접속 → 내비게이션 바 우측 끝 확인.
- 심각도: `P0 차단` — 세 기능이 조작 자체가 불가능함.
- 발생 가능성: 매우 높음 — iPhone SE(375)·iPhone 12 mini(375)·구형 안드로이드(360) 등 소형 화면 기종에서 100% 재현. 참고로 `src/ui/styles.ts`의 `WRAP`이 좌우 최소 24px 패딩을 강제하므로, 화면이 넓어져도 내비게이션 항목이 늘어날 때마다 이 여유폭은 계속 줄어드는 구조적 문제다.
- 영향받는 다른 페르소나: 전원. 특히 스마트폰에 익숙하지 않은 중장년 사용자(페르소나 7)는 "버튼이 안 보인다"를 "기능이 없다"로 오인하고 이탈할 가능성이 높다.
- 개선 방향: (a) 내비게이션 항목 수를 줄이거나 자주 안 쓰는 항목(가이드·팁)을 설정 메뉴 하위로 통합, (b) 좌우 탭 그룹과 우측 유틸 그�지 사이에 `overflow-x: auto`+스크롤 스냅 적용, (c) 우측 유틸을 "더보기(⋯)" 오버플로 메뉴로 압축 — 중 하나 이상. 지금까지의 회귀 테스트가 전부 데스크톱 폭으로 진행돼 이 문제를 놓쳐온 만큼, 앞으로는 모바일 뷰포트 확인을 회귀 테스트 표준 절차에 넣어야 한다.
- 실제 사용자 검증 필요 여부: 아니오 — 코드·DOM 측정으로 이미 확정적 결함.

### P1-1. "여행 현장에서 문장을 확대해 상대방에게 보여주는" 기능이 앱 전체에 없음

- 발생 위치: 앱 전역(`OrderCard.tsx`, `Review.tsx`의 `PhraseList`, `PublicExpressions.tsx`, `Emergency.tsx` 등 문장을 노출하는 모든 화면)
- 증거 유형: `[코드 확인]`
- 실제로 발생한 일: "확대", "크게 보기", "zoom", "보여주" 등의 키워드로 `src/views/*.tsx` 전체를 검색한 결과, 문장을 전체화면으로 확대해 상대방이 읽게 하는 기능이 존재하지 않는다. 문장이 표시되는 화면들의 최대 폰트 크기를 확인한 결과 `OrderCard.tsx`에서 가장 큰 문장 표시도 19px(`ReadingAid fontSize={19}`)에 그친다. 복습장의 `PhraseList`도 일본어 문장을 18px로만 표시하며 옆의 44×44px 스피커 버튼은 재생 전용이지 확대 전용이 아니다.
- 사용자가 기대할 행동: 편의점·식당 등에서 "이 문장을 점원에게 보여주기" 버튼을 누르면 화면 전체에 큰 글씨(예: 32px 이상)로 해당 일본어 문장만 뜨는 전용 모드.
- 문제가 되는 이유: 이는 강도윤 페르소나 문서 자체가 "여행 현장 모드는 학습 모드와 달라야 한다"의 5가지 우선 기능 중 하나로 명시한 항목이며, 사용자가 요청한 11개 검증 흐름에도 명시적으로 포함된 핵심 여행 시나리오다. 일본어를 발화하지 못하는 사용자(페르소나 1·3)에게는 "화면을 보여주는 것"이 유일한 의사소통 수단인 경우가 많다.
- 재현 단계: 복습장 > 표현 탭에서 학습한 문장 아무거나 확인 → 확대 옵션 없음. 홈 화면의 "오늘의 여행 미션" 카드도 문장이 있지만 확대 버튼 없음.
- 심각도: `P1 심각` — 여행 현장 핵심 과업 중 하나가 아예 수행 불가능.
- 발생 가능성: 100%(기능 부재이므로 항상 발생).
- 영향받는 다른 페르소나: 특히 페르소나 1(완전 초보), 페르소나 3(듣기만 되고 발화가 어려운 사용자), 페르소나 7(중장년).
- 개선 방향: 문장이 노출되는 화면(특히 미션 세션, 복습장 표현 카드)에 "크게 보여주기" 아이콘을 추가하고, 탭하면 배경을 어둡게 깔고 해당 일본어 문장만 초대형 글씨(가로 폭 꽉 채움)로 표시하는 전용 오버레이를 신설.
- 실제 사용자 검증 필요 여부: 기능 부재 자체는 확정적이나, 실제 여행 중 이 기능을 얼마나 자주 쓰는지(문장 표시 vs 음성 재생 vs 손짓)는 실사용자 검증이 필요하다.

## 4. 화면별 상세 문제

### A. 히라가나 표(가나·표 학습) — 정보 과다 후 학습 시작

- 위치: 학습 탭 > 히라가나 카드 클릭 → "히라가나 한눈에"
- 증거 유형: `[실행 확인]`
- 실제로 발생한 일: 청음 46자 + 탁음·반탁음 20자 + 요음 33자, 총 99자(+ん)가 3개 구획으로 한 화면에 전부 나열된 뒤에야 "15자/30자/50자/전체" 퀴즈 문항 선택과 시작 버튼이 나온다. 스크롤 없이 화면에 들어오는 글자 수는 5×3=15개 남짓이고 나머지는 전부 스크롤해야 한다.
- 사용자가 기대할 행동: 완전 초보자가 "오늘 배울 15자"만 먼저 마주하고, 전체 표는 "더 보기"로 접어둔 선택적 참고 자료가 되는 것.
- 문제가 되는 이유: "한 화면에는 하나의 주목적"과 배치된다 — 이 화면의 주목적은 "15자 퀴즈 시작"인데 그 앞에 99자 전체 표가 먼저 온다. 완전 초보자는 "이걸 다 외워야 하나"라는 인상을 받을 수 있다.
- 재현 단계: 학습 탭 → 히라가나 카드 클릭.
- 심각도: `P3 개선`
- 발생 가능성: 높음(입문 단계 사용자 전원이 처음 마주치는 화면).
- 영향받는 다른 페르소나: 페르소나 1(완전 초보), 페르소나 7(중장년, 스크롤 부담).
- 개선 방향: 전체 표는 기본 접힘(토글) 처리하고, "청음 15자" 같은 하위 묶음과 퀴즈 시작 버튼을 화면 상단으로 끌어올리는 구조 검토.
- 실제 사용자 검증 필요 여부: 아니오(정보 구조 문제로 판단 가능).

### B. 가나 상세 카드(KanaDetail) — 소리를 다시 들을 방법이 없음

- 위치: 히라가나 표에서 글자 하나를 탭했을 때 뜨는 상세 모달(`src/views/KanaTable.tsx:184-188`)
- 증거 유형: `[코드 확인]` + `[실행 확인]`
- 실제로 발생한 일: 모달이 열리면(또는 이전/다음으로 글자가 바뀌면) `useEffect`가 150ms 후 `speak(item.char)`를 **딱 한 번만** 호출한다. 글자 자체(`<div>{item.char}</div>`, 44px 큰 글씨)는 일반 `div`이지 `button`이 아니라 클릭해도 아무 반응이 없다(직접 클릭해 확인, 새 오디오 요청이 발생하지 않음). 모달 안에 재생 버튼은 하단의 "이 글자가 들어간 단어" 예시어에만 있고, 정작 지금 배우는 글자 자체를 재생하는 버튼은 없다.
- 사용자가 기대할 행동: 발음을 놓쳤거나 다시 듣고 싶을 때 글자를 탭하거나 별도 스피커 아이콘을 눌러 즉시 재생.
- 문제가 되는 이유: "음성 재생과 따라 말하기"는 사용자가 요청한 핵심 검증 흐름이다. 자동재생 1회는 놓치기 쉽고(모달이 열리자마자 다른 곳을 보고 있었다면), 다시 들으려면 "다음"→"이전"으로 왕복하는 우회 조작이 필요하다.
- 재현 단계: 학습 탭 > 히라가나 카드 > 아무 글자나 탭 > 큰 글자 부분 탭(반응 없음).
- 심각도: `P2 중요`
- 발생 가능성: 높음(청각 환경이 안 좋거나 재생을 놓치는 경우 흔함).
- 영향받는 다른 페르소나: 페르소나 3(듣기 의존도 높음), 페르소나 7(반응 속도가 느려 재생을 놓치기 쉬움).
- 개선 방향: 글자 표시 영역 자체를 버튼으로 바꾸거나 옆에 명시적 스피커 아이콘 추가.
- 실제 사용자 검증 필요 여부: 아니오.

### C. 가나 읽기 퀴즈에 상황회화용 피드백 문구 재사용

- 위치: 히라가나 퀴즈 오답 시 피드백(`ちゅ` 문제에서 확인)
- 증거 유형: `[실행 확인]`
- 실제로 발생한 일: 순수 글자-소리 매칭 문제(ちゅ의 소리는?)에서 오답을 고르니 "이 상황에선 어색해요 — 문맥과 맞지 않아 듣는 사람이 갸웃할 수 있어요. 자연스러운 답 → ちゅ ー 추"라는, 상황 회화용 자연스러움 피드백 문구가 그대로 나타났다.
- 사용자가 기대할 행동: 가나 읽기 문제라면 "정답은 '추'예요, ちゅ와 다시 헷갈리지 마세요" 같은 발음 중심 피드백.
- 문제가 되는 이유: "이 상황에선"이라는 표현은 대화 맥락이 있는 문제에는 맞지만 글자 하나의 발음 문제에는 어색하다. 완전 초보자는 "상황"이라는 단어에 오히려 더 혼란스러워할 수 있다.
- 재현 단계: 히라가나 15자 퀴즈에서 아무 문제나 오답 선택.
- 심각도: `P4 미세조정`
- 발생 가능성: 높음(모든 가나 퀴즈 오답에서 발생할 가능성 — 공통 피드백 컴포넌트 재사용으로 추정).
- 영향받는 다른 페르소나: 전원(사소하지만 전 사용자에게 노출).
- 개선 방향: 가나 읽기류 문제에는 별도의 짧은 오답 피드백 문구 사용(코드 확인 필요 — 공통 컴포넌트인지 확인 후 조건 분기).
- 실제 사용자 검증 필요 여부: 아니오.

### D. 수집함(가챠) — 입문 단계 사용자에게 54개 잠금 카드 전부 노출

- 위치: 수집함 탭 > ALL SCENES 섹션
- 증거 유형: `[실행 확인]`
- 실제로 발생한 일: 입문 단계(미션 자체가 아직 열리지 않는 레벨)임에도 "미션을 완료하면 카드가 열려요"라는 동일한 잠금 카드가 54개 전부 세로로 나열된다(편의점부터 실내·길거리·병원 등 중복 지명 포함).
- 사용자가 기대할 행동: 지금 단계에서 의미 없는 콘텐츠는 요약("전체 54장 중 아직 열린 장면 없음")으로 압축하고, 실제 도달 가능한 시점(중급 승급 후)에 자연스럽게 펼쳐지는 것.
- 문제가 되는 이유: "게임화는 학습을 지원해야 한다"는 원칙과 배치 — 아직 아무 것도 할 수 없는 화면을 길게 스크롤하게 만드는 것은 학습 동기를 주기보다 "복잡한 화면"이라는 인상만 남긴다.
- 재현 단계: 신규 계정(입문) 상태로 수집함 탭 진입 → 아래로 스크롤.
- 심각도: `P3 개선`
- 발생 가능성: 높음(모든 신규 사용자가 온보딩 중 한 번쯤 들여다볼 화면).
- 영향받는 다른 페르소나: 페르소나 1, 페르소나 7.
- 개선 방향: 미션이 잠긴 레벨(입문·기본)에서는 54개 개별 카드 대신 "미션은 중급부터 열려요 + 진행률 요약"으로 압축, 미션 지도의 잠금 그리드 패턴(자물쇠 압축 그리드)과 통일.
- 실제 사용자 검증 필요 여부: 아니오.

### E. 퀴즈 중도 이탈 시 확인 절차 없음

- 위치: 세션 화면 상단 "나가기" 버튼
- 증거 유형: `[실행 확인]`
- 실제로 발생한 일: 15문항 중 1문항만 푼 상태에서 "나가기"를 누르면 즉시 확인 없이 이전 화면(가나 표)으로 돌아간다.
- 사용자가 기대할 행동: 큰 문제는 아니나(이미 푼 문항은 SRS에 저장되어 진도 손실은 없음), 실수로 누른 경우를 대비한 짧은 확인(예: 1초 內 재탭 취소 토스트)이 있으면 더 안전하다.
- 문제가 되는 이유: 손이 크거나 화면 조작이 서툰 사용자(페르소나 7)가 실수로 세션을 중단시킬 위험.
- 재현 단계: 임의 학습 세션 진입 → 상단 "나가기" 탭.
- 심각도: `P4 미세조정`(데이터 손실은 없으므로 낮게 평가)
- 발생 가능성: 중간.
- 영향받는 다른 페르소나: 페르소나 7.
- 개선 방향: 필요성이 낮아 우선순위는 낮음 — 실사용자 관찰 후 결정 권장.
- 실제 사용자 검증 필요 여부: 예 — 실제로 오조작이 빈번한지 확인 필요.

### F. 가나 표의 모든 셀이 동일한 접근성 이름("아직")을 가짐

- 위치: 히라가나/가타카나 표 그리드 버튼
- 증거 유형: `[코드 확인]`(`read_page` 접근성 트리에서 모든 미학습 셀이 "아직"으로만 표시됨을 확인)
- 문제가 되는 이유: 스크린리더 사용자에게는 46개 이상의 버�른이 전부 "아직"으로만 들려 어떤 글자인지 구분이 불가능하다. 이번 페르소나 세트에는 시각장애 사용자가 명시적으로 포함되어 있지 않아 우선순위는 낮게 잡되, 접근성 일반 원칙상 기록해 둔다.
- 심각도: `P4 미세조정`
- 개선 방향: `aria-label`에 실제 글자(로마자 포함)를 명시.
- 실제 사용자 검증 필요 여부: 아니오.

## 5. 텍스트 밀도가 높은 화면

- 히라가나/가타카나 "한눈에" 표 전체(§4-A) — 스크롤 압박 최상위.
- 수준 진단의 "상황 회화" 문제(12/16, 16/16 등) — 일본어 프롬프트 + 한국어 상황 설명 + 안내문 + 안심 문구 + 4지선다가 한 화면에 모두 들어있다. 다만 이건 실제 실력을 재는 구간이라는 걸 미리 알려주는 안내문(💡 이 구간은 실제 일본어 실력을 그대로 측정해요...)이 불안을 줄여주므로, 밀도는 높지만 목적에 부합해 삭제 대상은 아니라고 판단.
- 수집함 ALL SCENES 리스트(§4-D) — 밀도라기보다 "반복되는 동일 패턴의 길이"가 문제.

## 6. 초보자가 이해하기 어려운 화면

- 특별히 "이해 자체가 안 되는" 화면은 발견하지 못했다. 다만 §4-A(전체 표 우선 노출)는 "여기서 뭘 해야 하지"에 대한 답을 늦게 준다는 점에서 이해도보다 방향성 문제에 가깝다.

## 7. 게임화가 학습을 방해하는 부분

- 직접적으로 학습 진행을 막거나 강제로 게임 화면을 거치게 하는 사례는 발견하지 못했다(가챠는 별도 탭, 세션 완료 후 보상도 선택적으로 보임). §4-D(수집함 잠금 카드 과다)는 "방해"라기보다 "이 시점에 무의미한 콘텐츠 과다 노출"에 가깝다.

## 8. 중장년층 접근성 문제

- **P0-1(내비게이션 바 잘림)**이 가장 직접적인 접근성 문제 — 작은 화면 기기를 쓸 가능성이 높은 이 사용자군에게 설정 진입 자체가 막힌다.
- 글자 크기 자체는 전반적으로 무난하다(본문 13~17px, 강조 22px 이상). 작은 글씨로 인한 가독성 문제는 이번 조작 범위에서는 발견하지 못했다.
- §4-E(나가기 확인 없음)도 조작 실수에 취약한 이 사용자군과 관련이 있다.

## 9. 여행 현장 사용성 문제

- **P1-1(문장 확대 기능 부재)**이 핵심 문제.
- 긴급 화면은 반대로 강점(§2)으로 평가한다.
- 표현 검색(§2)도 여행 중 "이 말 어떻게 해요?"를 빠르게 찾는 데 유효하게 작동한다(단, 검색 자체는 홈 화면이 아니라 복습장 > 표현 탭에 있어 진입 경로가 한 번 더 필요하다는 점은 참고할 만하다 — 이번 조사에서는 별도 문제로 등록하지 않고 §12에 개선 후보로만 남긴다).

## 10. 삭제 또는 축소할 요소

- 수집함의 54개 개별 잠금 카드 → 레벨 조건 요약으로 축소(§4-D).
- 히라가나/가타카나 전체 표를 학습 시작 화면에서 기본 노출 → 접힘 처리로 축소(§4-A).

## 11. 유지하거나 강화할 요소

- 진단 결과 화면의 톤과 다음 행동 제시(§2) — 강화 여지: 다른 결과 화면(승급 시험 결과 등)에도 같은 패턴 확산.
- 표현 검색의 "학습하면 나타나요" 잠금 프리뷰 패턴(§2) — 강화 여지: 장면별 탭에도 이미 유사 패턴이 있으나 일관되게 전체 앱에 문서화해 재사용.
- 긴급 화면의 즉시 접근성(§2) — 유지.
- 퀴즈 하단 "문장을 탭하면 다시 들을 수 있어요" 상시 안내(§2) — 유지. 다만 §4-B에서 지적한 가나 상세 모달에는 이 패턴이 없으므로 그쪽에도 확산 필요.

## 12. 빠른 개선 항목

- 가나 읽기 퀴즈 오답 피드백 문구 분기(§4-C)
- 가나 상세 모달에 재생 버튼 추가(§4-B)
- 나가기 확인 토스트(§4-E, 실사용자 검증 후 결정)
- 가나 표 셀 aria-label 개선(§4-F)

## 13. 구조적 개선 항목

- 내비게이션 바 오버플로 해결(P0-1) — 항목 재구성 또는 스크롤/더보기 처리.
- 문장 확대 오버레이 신설(P1-1) — 여러 화면에 공통 적용될 컴포넌트 설계 필요.
- 수집함 레벨별 콘텐츠 압축(§4-D).
- 히라가나/가타카나 학습 화면 정보 구조 재배치(§4-A).

## 14. 구현 작업 목록

이 감사 단계에서는 우선순위 확정 전이므로 구체 작업 목록은 5단계(개선 백로그)·6단계(구현 계획) 산출물로 넘긴다. 여기서는 후보만 나열했다(§12, §13).

## 15. 개선 후 회귀 테스트 과업

- **모바일 뷰포트(최소 360~375px 폭)에서 내비게이션 바 전 항목 도달 가능 여부**를 향후 모든 회귀 테스트의 표준 절차에 추가할 것(이번 감사 전까지 누락되어 있었음).
- 문장 확대 기능 신설 시: 편의점·식당·긴급 화면 각각에서 실제로 확대 모드가 뜨는지, 배경 대비가 충분한지 확인.
- 가나 상세 모달 재생 버튼: 클릭 시 실제 네트워크 요청(또는 Web Speech 호출)이 발생하는지 확인.
- 수집함 화면: 입문/기본/중급/고급 각 레벨에서 카드 리스트 표시가 레벨에 맞게 압축·확장되는지 확인.
