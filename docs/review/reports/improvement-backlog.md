# 5단계 — 개선 백로그

> 등록 기준(하나 이상 충족): 주요 과업을 방해함 / 여러 사용자에게 영향을 줌 / 학습 효과를 저하시킴 / 여행 현장에서 실패 가능성을 높임 / 구현 비용 대비 효과가 큼. 1~4단계 산출물에서 이 기준을 충족하는 항목만 선별했다. 아직 코드는 수정하지 않는다.

### BL-01. 모바일 좁은 화면에서 내비게이션 바 3개 메뉴(팁·가이드·설정)가 화면 밖으로 잘려 조작 불가능

- **문제 설명**: 375px 폭(iPhone SE/6/7/8/X급)에서 `nav` 요소의 `scrollWidth`(520px)가 `clientWidth`(327px)를 초과하고 `overflow-x: visible`·`flex-wrap: nowrap`이라 팁·가이드·설정 버튼이 화면 밖으로 밀려나며, 페이지 자체도 가로 스크롤되지 않아 어떤 방법으로도 도달 불가능하다.
- **발견한 전문가**: 강도윤(UX) — ux-expert-audit.md P0-1
- **영향받는 사용자**: 전원. 페르소나 1(진단 재조정·발음 보조 조절 불가), 2(수동 레벨 상향으로 미션 조기 진입 불가), 7(속도 조절·설정 전반 불가) — persona-validation.md에서 직접 확인.
- **관련 화면**: `NavBar`(모든 허브 화면 공통)
- **관련 학습 문형**: 해당 없음(순수 UI 결함)
- **심각도**: P0 차단
- **개선 제안**: 내비게이션 항목 재구성(가이드·팁을 설정 하위로 통합) 또는 우측 유틸 영역에 `overflow-x: auto` 적용, 혹은 "더보기(⋯)" 오버플로 메뉴 도입.
- **구현 범위**: `src/views/NavBar.tsx` 레이아웃 수정(소규모~중규모, 신규 컴포넌트 없이 기존 구조 조정으로 가능).
- **검증 방법**: 360~375px 폭에서 11개 내비게이션 항목 전부가 탭 가능한지 좌표 측정으로 재확인. 이후 모든 회귀 테스트에 모바일 뷰포트 확인을 표준 절차로 추가.
- **실제 사용자 검증 필요 여부**: 아니오(코드·DOM으로 이미 확정).

### BL-02. 여행 현장에서 문장을 확대해 상대방에게 보여주는 기능이 앱에 없음

- **문제 설명**: "확대", "크게 보기" 등 관련 기능이 전체 코드베이스에 존재하지 않으며, 문장이 표시되는 화면의 최대 폰트 크기도 19px에 그친다.
- **발견한 전문가**: 강도윤(UX) — ux-expert-audit.md P1-1
- **영향받는 사용자**: 페르소나 1(발화 불가 시 화면 제시가 유일한 수단), 3, 7 — persona-validation.md에서 확인.
- **관련 화면**: 미션 세션, 복습장 표현 카드, 긴급 화면 등 문장이 노출되는 전 화면
- **관련 학습 문형**: 해당 없음(기능 부재)
- **심각도**: P1 심각
- **개선 제안**: 문장 카드에 "크게 보여주기" 아이콘 추가 → 탭 시 배경을 어둡게 깔고 해당 일본어 문장만 초대형 글씨(가로 폭 꽉 채움)로 표시하는 오버레이 신설.
- **구현 범위**: 신규 공용 컴포넌트 1개(오버레이) + 기존 문장 카드들에 버튼 추가(중규모).
- **검증 방법**: 편의점·식당·긴급 화면 각각에서 확대 모드 진입·가독성(야외 밝기 가정) 확인.
- **실제 사용자 검증 필요 여부**: 기능 부재 자체는 확정적이나, 실제 여행 중 사용 빈도는 실사용자 검증 대상(cross-review §5).

### BL-03. 입문→중급 전환이 점진적 곡선이 아니라 이진 스위치

- **문제 설명**: 미션(장면 회화) 카드 배정이 입문 0개·기본 0개 → 중급 10개로 한 번에 뛰고, 이에 따라 수집함에는 54개 잠금 카드가 그대로 노출된다. 두 전문가가 서로 다른 각도(UX: 화면 과다 노출 / 학습: 교육 곡선 단절)에서 같은 구조를 지적했다.
- **발견한 전문가**: 강도윤(UX) + 한서연(학습) — expert-cross-review.md §1
- **영향받는 사용자**: 페르소나 1, 2 — persona-validation.md에서 실제 과업 차단 확인(단, 설정에서 수동으로 레벨을 올리는 저발견성 우회로는 존재).
- **관련 화면**: 학습 지도(Practice), 미션 지도(Map), 수집함(Gacha)
- **관련 학습 문형**: 전체 문형 학습 → 상황 학습 전환 구조 자체
- **심각도**: P1 심각(UX 기준) / 구조적 개선 필요(학습 기준)
- **개선 제안**: (a) 입문·기본 단계에서도 미션 1~2개를 "맛보기"로 조기 개방하거나, (b) 수동 레벨 상향 기능을 설정 깊은 곳이 아니라 홈 화면에 "급하신가요? 미션으로 바로 가기" 형태로 발견 가능하게 노출, (c) 수집함의 잠금 카드는 레벨에 맞춰 압축 표시(BL-08과 연계).
- **구현 범위**: 정책 결정 필요(어느 정도까지 조기 개방할지) + Practice/Map/Home 화면 수정(중규모~대규모).
- **검증 방법**: 페르소나 1·2 재현 시나리오로 "편의점 미션 도달까지 걸리는 세션 수" 측정, 개선 전후 비교.
- **실제 사용자 검증 필요 여부**: 예 — 조기 개방이 학습 순서를 해치지 않는지는 실사용자 반응이 필요.

### BL-04. "〜はどこですか" 등 이미 존재하는 문장들이 문형으로 묶여 있지 않음

- **문제 설명**: phrases.ts·grammar.ts에 흩어진 최소 14개 문장이 전부 같은 "OOはどこですか" 틀인데, 이를 하나의 재사용 패턴으로 명시하는 화면·데이터가 없다.
- **발견한 전문가**: 한서연(학습) — learning-expert-audit.md §4-A
- **영향받는 사용자**: 전체 학습자(패턴 인지를 통한 학습 효율 저하)
- **관련 화면**: 신규 도입 필요(기존 세션 카드에 얇은 레이어로 절충안 — expert-cross-review.md §4-1)
- **관련 학습 문형**: Aはどこですか
- **심각도**: 학습 효과 저하(중간)
- **개선 제안**: 신규 문장 제작 없이 기존 문장을 그룹화하고, cross-review §4-1에서 합의한 절충안(예시 병렬 카드 + 처음 1회만 전체 설명 + 이후 배지만 + 선택적 상세)으로 구현.
- **구현 범위**: 문형 그룹 id 데이터 추가(소규모) + 카드 UI 레이어 신설(중규모). **단, 신규 문장 제작은 불필요 — 가장 비용 대비 효과가 큰 항목.**
- **검증 방법**: 문형 그룹 카드 노출 후 동일 패턴 문장(예: 코인로커는 어디예요) 학습 시 사용자가 "이미 배운 패턴"임을 인지하는지 확인(실사용자 관찰 필요).
- **실제 사용자 검증 필요 여부**: 예 — 패턴 인지 효과 자체는 실사용자 검증 대상.

### BL-05. 고급 문형 9개가 tier 미지정으로 조기 노출 위험

- **문제 설명**: `〜たり〜たりする`, `〜すぎる`, `〜んです`, `〜そうです`, `〜ば`, `〜たことがあります` 등 N4 후반~N3 수준 문형 9개가 `GRAMMAR_LEVEL` 맵에 명시적 tier 지정이 없어 기본값 tier 2("생활" 수준)로 취급된다.
- **발견한 전문가**: 한서연(학습) — learning-expert-audit.md §6
- **영향받는 사용자**: 입문·기본 단계 학습자 전체(잠재적)
- **관련 화면**: 세션 진입 시 팁 카드(전 화면 공통)
- **관련 학습 문형**: 위 9개 문형
- **심각도**: 학습 효과 저하 위험(발생 여부는 추가 코드 확인 필요, learning-expert-audit.md §6 참고)
- **개선 제안**: `src/content/grammar.ts`의 `GRAMMAR_LEVEL` 맵에 9개 항목에 tier 4 이상 명시.
- **구현 범위**: 데이터 한 줄 수정 9건(매우 낮음, 화면 변경 없음).
- **검증 방법**: 수정 후 입문·기본 레벨 세션에서 해당 9개 팁이 실제로 노출되지 않는지 확인.
- **실제 사용자 검증 필요 여부**: 아니오.

### BL-06. あります/います(존재 동사) 구분 콘텐츠 전무

- **문제 설명**: 무생물 존재 표현(あります)은 15회 등장하지만 생물 존재 표현(います)은 전체 콘텐츠에 단 한 번도 등장하지 않는다. 한국어 "있다"가 이 구분을 하지 않아 실제 회화에서 오류 위험이 있다.
- **발견한 전문가**: 한서연(학습) — learning-expert-audit.md §7-A
- **영향받는 사용자**: 전체 학습자, 특히 미아 찾기 등 안전 관련 상황에서 실사용 위험
- **관련 화면**: 문법 팁 풀, 관련 미션(C53 미아 찾기 등)
- **관련 학습 문형**: Aがいます / Aがあります 구분
- **심각도**: 여행 현장 실패 가능성 있음(중간)
- **개선 제안**: います 사용 예문 1~3개와 전용 문법 팁("사물은 あります, 사람·동물은 います") 신규 추가.
- **구현 범위**: 신규 문장 1~3개 + 문법 팁 1개(중간 — 원어민 검수 필요, learning-expert-audit.md §13).
- **검증 방법**: `lint:content` 통과 + 원어민 검수 + 세션에서 실제 노출 확인.
- **실제 사용자 검증 필요 여부**: 콘텐츠 정확성은 원어민 검수 대상이며, 학습 효과는 실사용자 검증 권장.

### BL-07. 가나 상세 모달(KanaDetail)에 재생 반복 버튼 없음

- **문제 설명**: 모달이 열릴 때 글자 소리가 150ms 후 한 번만 자동 재생되고, 글자 자체나 별도 버튼으로 재생을 반복할 방법이 없다(직접 클릭 확인, 새 오디오 요청 미발생).
- **발견한 전문가**: 강도윤(UX) — ux-expert-audit.md §4-B (동시에 한서연의 "듣기 반복" 철학과도 부합, 학습 효과에 긍정적)
- **영향받는 사용자**: 페르소나 1, 3(듣기 의존), 7(반응 속도 느려 재생 놓치기 쉬움)
- **관련 화면**: `src/views/KanaTable.tsx`의 `KanaDetail` 모달
- **관련 학습 문형**: 가나 발음 전반
- **심각도**: P2 중요
- **개선 제안**: 글자 표시 영역을 버튼화하거나 옆에 스피커 아이콘 추가.
- **구현 범위**: 소규모(기존 `speak()` 호출 재사용, 버튼 하나 추가).
- **검증 방법**: 클릭 시 실제 오디오 요청(또는 Web Speech 호출) 발생 확인.
- **실제 사용자 검증 필요 여부**: 아니오.

### BL-08. 수집함(가챠) 화면에 입문 단계 사용자용 54개 잠금 카드 전부 노출

- **문제 설명**: 미션이 잠긴 레벨(입문·기본)에서도 54개 미션 잠금 카드가 개별로 전부 나열된다.
- **발견한 전문가**: 강도윤(UX) — ux-expert-audit.md §4-D
- **영향받는 사용자**: 페르소나 1, 7(스크롤 부담)
- **관련 화면**: `src/views/Gacha.tsx`(수집함 ALL SCENES 섹션)
- **관련 학습 문형**: 해당 없음
- **심각도**: P3 개선
- **개선 제안**: 미션이 잠긴 레벨에서는 개별 카드 대신 "미션은 중급부터 열려요 + 진행률 요약"으로 압축(미션 지도의 잠금 그리드 패턴과 통일).
- **구현 범위**: 중간(레벨 조건 분기 추가).
- **검증 방법**: 입문/기본/중급/고급 각 레벨에서 카드 리스트 표시가 레벨에 맞게 압축·확장되는지 확인.
- **실제 사용자 검증 필요 여부**: 아니오.

### BL-09. 가나 읽기 퀴즈에 상황회화용 오답 피드백 문구 재사용

- **문제 설명**: 순수 글자-소리 매칭 문제에서 "이 상황에선 어색해요"(원래 상황 회화의 자연스러움 피드백용) 문구가 그대로 노출된다.
- **발견한 전문가**: 강도윤(UX) — ux-expert-audit.md §4-C
- **영향받는 사용자**: 전체 학습자
- **관련 화면**: 히라가나/가타카나 퀴즈 오답 피드백
- **관련 학습 문형**: 해당 없음(가나 읽기)
- **심각도**: P4 미세조정
- **개선 제안**: 가나 읽기류 문제 전용의 짧은 오답 피드백 문구로 분기.
- **구현 범위**: 소규모(공통 피드백 컴포넌트에 조건 분기 추가 — 코드 위치 확인 필요).
- **검증 방법**: 가나 퀴즈 오답 시 새 피드백 문구 노출 확인.
- **실제 사용자 검증 필요 여부**: 아니오.

### BL-10. 〜てもいいですか 문법 팁 중복 등록

- **문제 설명**: `g_mo_ii`와 `g_grammar_temo_ii`가 완전히 같은 문형을 서로 다른 id로 중복 등록하고 있다.
- **발견한 전문가**: 한서연(학습) — learning-expert-audit.md §4-B
- **영향받는 사용자**: 전체 학습자(같은 팁을 중복 학습하게 될 가능성)
- **관련 화면**: 세션 진입 시 팁 카드
- **관련 학습 문형**: Vてもいいですか
- **심각도**: 콘텐츠 정리 필요(낮음)
- **개선 제안**: 두 항목 중 하나로 통합, 참조(`missionIds`, `grammarRefs`) 정리.
- **구현 범위**: 매우 낮음(콘텐츠 정리).
- **검증 방법**: `lint:content` 통과 확인.
- **실제 사용자 검증 필요 여부**: 아니오.

## 이번 백로그에서 제외한 항목과 이유

- 가나 표 전체 선노출(§4-A, ux-expert-audit.md): 완전 삭제가 아니라 "접기" 절충으로 cross-review §4-2에서 이미 낮은 비용 해법이 합의됨 — 별도 백로그 항목보다 BL-03/구현계획에서 함께 처리.
- 세션 중도 이탈 확인 없음(§4-E): 데이터 손실이 없어 "주요 과업 방해"에 해당하지 않는다고 판단, 실사용자 오조작 빈도 확인 후 재등록 여부 결정(cross-review §5).
- 가나 표 셀 aria-label 동일 문제(§4-F): 이번 페르소나 세트에 시각장애 사용자가 없어 우선순위 기준 미달로 제외(추후 접근성 전용 감사에서 재검토 권장).
- Vたいです/も/が必要です/がいいです 등 나머지 빠진 문형(learning §5): BL-04(문형 그룹화)와 성격이 겹치는 후속 콘텐츠 작업으로, 이번 백로그는 가장 시급하고 비용 대비 효과가 큰 Aはどこですか만 대표로 등록. 나머지는 BL-04 완료 후 같은 패턴으로 순차 추가 권장.
