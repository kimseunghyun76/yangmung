# 페르소나 3: 귀는 트였지만 읽지 못하는 사용자

> 합성 페르소나 테스트 결과. 실제 사용자 데이터가 아님.

## 1. 페르소나 요약
애니메이션·드라마 시청으로 듣기는 어느 정도 되지만 히라가나/가타카나를 읽지 못하는 사용자.

## 2. 테스트 환경
- `[코드 확인]` 위주. 수준진단 분류 로직은 소스 코드(`src/views/Placement.tsx:52-125`)를 직접 읽어 분기 조건을 확인했으며, 페르소나 1의 실행 테스트에서 확보한 진단 UI 동작(문항 형식, 진행 방식)을 함께 활용함. 이 페르소나 특유의 응답 패턴(듣기 정답·읽기 오답)으로 진단을 새로 플레이하지는 않았음 — 분류 결과는 코드 분석으로 도출.

## 3. 수행한 과업
1. 듣기와 읽기 수준이 다른 사용자로 진단받기
2. 이미 알고 있는 기초 표현 건너뛰기
3. 편의점 직원의 질문 듣기
4. 비슷하게 들리는 표현 구분하기
5. 가나와 발음 보조를 함께 사용하기

## 4. 완료한 과업 (코드 분석 기반 추정)
- **듣기/읽기 수준 분리 진단**: `[코드 확인]` `recommend(read, listen, situation)` 함수(`Placement.tsx:52`)는 3축을 완전히 독립적으로 채점한다. `listenStrong(≥0.7) && readWeak(<0.5)` 조건이 참이면 무조건 "귀가 먼저 트인 여행자" 프로필로 분류되며(69-77행), 다른 조건보다 **우선순위가 가장 높게** 배치되어 있어(균형형 분기보다 먼저 체크) 이 페르소나가 "균형 잡힌 여행자"나 "설레는 첫 여행자"로 뭉뚱그려질 위험이 없다. **완료로 판단**(코드 확인 기준).
- **가나와 발음 보조 함께 사용**: `[코드 확인]` 이 프로필은 `mode: 'express', readingAid: 'auto'`로 설정된다(74행). `express` 모드는 가나를 스킵하지 않으므로(`markKana: false`) 가나 학습은 유지하면서, 읽기 보조(로마자/한글)는 자동으로 켜진 상태로 시작한다 — "가나 학습을 새로 하되 보조는 받는다"는 요구에 부합.

## 5. 실패하거나 중단된 과업
- **이미 아는 기초 표현 건너뛰기**: `[코드 확인]` `markKana: false`이므로 가나 트랙은 스킵되지 않는다. 이 페르소나는 가나를 "읽지" 못할 뿐 기초 인사말 등 구두 표현 자체는 알고 있을 수 있는데, 진단이 구분하는 것은 어디까지나 읽기/듣기/상황 3축의 정답률이지 "이미 아는 표현 목록"이 아니므로, 이미 아는 표현이 새 표현으로 다시 나올 가능성을 배제할 수 없다. `[추론]` — 실제 중복 여부는 세션을 끝까지 진행해봐야 확인 가능.
- **편의점 직원 질문 듣기 / 비슷하게 들리는 표현 구분**: `[실사용자 검증 필요]` 미션 콘텐츠 자체(C1 편의점)는 중급 승급 후에나 열리므로(F3, persona-01 참고), 이 페르소나도 첫 세션에 편의점 미션에 도달하지 못할 수 있다. 다만 "중급"으로 배치되므로 페르소나 1보다는 승급까지의 거리가 짧을 것으로 추정(`[추론]`).

## 6. 발견한 문제

### 문제 1: 상황회화 진단 문항이 "듣기 강자"에게도 읽기 편향적
- **페르소나**: 3
- **발생 위치**: 수준진단 12~16번 문항
- **수행하려던 과업**: 정확한 진단 받기
- **증거 유형**: `[실행 확인]`(문항 형식은 페르소나 1 테스트에서 직접 확인) + `[코드 확인]`
- **실제로 발생한 일**: 상황회화 축은 오디오 없이 텍스트(일본어)만으로 제시된다(`axisOf()`에서 `situation`은 `reviewTarget?.type === 'mission'` 카드, 즉 읽기 기반). 귀는 좋지만 눈이 약한 사용자는 이 축에서도 불리할 수 있다.
- **사용자가 기대할 행동**: 상황회화 문항도 음성으로 들려주면 이 페르소나의 실제 회화 이해력을 더 정확히 반영할 것.
- **문제가 되는 이유**: 다행히 `situWeak` 여부는 "귀가 먼저 트인 여행자" 분기(듣기+읽기 조건만 검사)에는 영향을 주지 않아 최종 분류 자체는 왜곡되지 않는다(코드 확인). 다만 진단 화면에 표시되는 "상황 회화 0%" 같은 점수가 사용자에게 불필요한 위축감을 줄 수 있다.
- **재현 단계**: 코드 확인 — `axisOf()`, `recommend()` 로직.
- **심각도**: S3 보통
- **발생 가능성**: 중간
- **영향받는 다른 페르소나**: 1
- **개선 방향**: 상황회화 문항에도 음성 재생 옵션 추가 검토.
- **실제 사용자 검증 필요 여부**: 예.

### 문제 2: "이미 아는 표현"을 사용자가 직접 알릴 방법 부재
- **페르소나**: 3
- **발생 위치**: 수준진단 전반, 학습 세션
- **증거 유형**: `[코드 확인]` + `[추론]`
- **실제로 발생한 일**: 진단은 정답률만 측정하며, "이 표현은 이미 실생활에서 써봤다"를 사용자가 직접 표시할 UI가 없다(설정에 "가나는 이미 알아요" 스킵 버튼은 있으나 개별 표현 단위가 아님).
- **문제가 되는 이유**: 애니·드라마로 이미 익숙한 상투구(예: いらっしゃいませ)가 "새 표현"으로 다시 소개될 경우 지루함을 유발할 수 있음.
- **심각도**: S3 보통
- **발생 가능성**: `[추론]` 중간
- **영향받는 다른 페르소나**: 4
- **개선 방향**: 개별 표현 단위 "이미 알아요" 스킵 기능 검토.
- **실제 사용자 검증 필요 여부**: 예 — 실제로 지루함을 느끼는지, 아니면 복습 차원에서 긍정적으로 받아들이는지.

## 7. 학습 콘텐츠 적합성
- `[코드 확인]` 분류 로직 자체는 이 페르소나를 정확히 인식하도록 설계되어 있어 설계 의도가 명확함(강점). 다만 콘텐츠가 "듣기 우선, 읽기는 따라오는" 순서로 실제 세션 안에서 재배열되는지는 `[실사용자 검증 필요]`.

## 8. 화면 및 조작 적조성
- `[추론]` `readingAid: 'auto'` 설정이 실제 세션에서 "필요할 때만" 자동으로 나타나는지, 아니면 상시 노출되는지는 세션을 끝까지 진행해야 확인 가능. `auto` 모드는 코드상 존재가 확인되나 그 발동 조건까지는 조사하지 않음.

## 9. 여행 현장 활용 가능성
- `[코드 확인]` 중급으로 배치되므로 미션 잠금(F3, persona-01) 문제의 영향을 페르소나 1보다는 덜 받을 것으로 추정되나, 근본적인 "무작위 순차 오픈" 구조 자체는 동일하게 적용됨.

## 10. 실제 사용자에게 검증해야 할 가설
- `readingAid: 'auto'`가 실제로 "모르는 가나만" 보조하는지, 사용자 체감상 자연스러운지.
- 이미 아는 상투 표현이 재등장할 때의 실제 반응(지루함 vs 복습 만족감).
- 상황회화 문항에 음성이 없어도 실제 진단 정확도에 문제가 없는지.

## 12. 이 페르소나에게 앱을 추천할 수 있는가
**조건부 가능 (검증 필요).** 수준진단이 이 페르소나를 "완전 초보"로 오분류하지 않고 정확히 식별한다는 점은 코드상 명확한 강점이다. 다만 실제 세션에서 그 분류가 체감 가능한 학습 경험 차이로 이어지는지, 그리고 미션 잠금 구조의 영향을 얼마나 받는지는 실사용자 검증이 필요하다.
