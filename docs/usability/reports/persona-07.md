# 페르소나 7: 스마트폰에 익숙하지 않은 중장년 사용자

> 합성 페르소나 테스트 결과. 실제 사용자 데이터가 아님.

## 1. 페르소나 요약
디지털 리터러시가 낮은 편인 중장년 사용자. 별도 설명 없이 앱을 바로 사용하려 함.

## 2. 테스트 환경
- `[실행 확인]` 데스크톱(1280×720)과 모바일 뷰포트(375×812) 양쪽에서 홈 화면 렌더링을 확인.
- `[코드 확인]` 음성 속도 조절(`LISTEN_RATES`, `settings.ts:35`), TTS 폴백 로직(`src/tts.ts`).
- 실제 오디오가 "들리는지"는 이 테스트 환경(자동화 브라우저)에서 청취로 검증할 수 없어 재생 버튼의 존재·클릭 가능 여부만 확인함. `[실사용자 검증 필요]` 항목으로 별도 표기.

## 3. 수행한 과업
1. 별도 설명 없이 첫 학습 시작
2. 음성 재생
3. 음성 속도 조절
4. 학습을 종료하고 다시 시작
5. 복습 화면 찾기
6. 여행 현장 문장 찾기

## 4. 완료한 과업
- **별도 설명 없이 첫 학습 시작**: `[실행 확인]` 온보딩 모달에서 "건너뛰고 기본으로 시작" 버튼이 있어, 설명을 읽지 않고 즉시 진입 가능. 다만 완전히 "설명 없이"는 아니고 모달 자체를 한 번은 닫아야 함(버튼 2개 중 택1).
- **음성 재생(버튼 존재 확인)**: `[실행 확인]` 학습 카드마다 헤드폰 아이콘 버튼이 있고 클릭 가능함을 확인. 실제 음성 출력 여부는 `[실사용자 검증 필요]`.
- **음성 속도 조절**: `[코드 확인]` 설정 화면에 속도 조절 UI(`SettingsModal.tsx:118-127`, 0.5~2배속 6단계)가 존재함을 코드로 확인. 실제 화면 조작까지는 하지 않았으나 설정 모달 진입 자체는 라이브로 확인됨(persona-01 테스트에서 설정 모달 오픈 확인).
- **복습 화면 찾기**: `[실행 확인]` 상단 네비게이션의 "복습" 탭 1클릭으로 도달. 위치가 명확함.

## 5. 실패하거나 중단된 과업
- **학습을 종료하고 다시 시작**: `[코드 확인]` 세션 중 "나가기" 버튼이 카드 화면 좌상단에 있음을 확인(persona-04 테스트의 세션 진행 중 `button "나가기"` 발견). 다만 실제로 나간 뒤 "이어서" vs "처음부터" 중 어떤 방식으로 재개되는지는 끝까지 확인하지 못함. `[실사용자 검증 필요]`.
- **여행 현장 문장 찾기**: `[코드+실행 확인]` 미션이 잠겨 있거나(입문/기본) 검색이 "이미 학습한 것"으로 제한되는 공통 구조적 문제(F1/F3, persona-01·02 참고)의 영향을 동일하게 받음.

## 6. 발견한 문제

### 문제 1: 상단 내비게이션이 아이콘 없이 순수 텍스트 라벨
- **페르소나**: 7
- **발생 위치**: 전역 상단 네비게이션 바 (홈/학습/미션/복습/도감)
- **수행하려던 과업**: 복습 화면 찾기 등 전반적 탐색
- **증거 유형**: `[실행 확인]` (모바일 375px 뷰포트 스크린샷으로 직접 확인)
- **실제로 발생한 일**: 5개 탭이 아이콘 없이 텍스트만으로 표시됨(약 14~16px 추정). 반대로 우측 유틸리티 버튼(테마 전환/문화팁/가이드/설정)은 아이콘만 있고 텍스트 라벨이 없음.
- **사용자가 기대할 행동**: 저시력이거나 디지털 기기에 익숙하지 않은 사용자는 아이콘+텍스트가 함께 있을 때 기능을 가장 빨리 유추함.
- **문제가 되는 이유**: 텍스트만 있는 5개 탭 중 "도감"은 게임 용어라 중장년층에게 즉각적으로 와닿지 않을 수 있고, 아이콘만 있는 우측 버튼 4개는 반대로 텍스트가 없어 기능을 짐작하기 어렵다. 두 그룹이 서로 다른 방식(텍스트 전용 vs 아이콘 전용)으로 표시되는 점도 일관성이 떨어짐.
- **재현 단계**: 홈 화면 상단 확인(데스크톱/모바일 공통).
- **심각도**: `[추론]` S3 보통 (실제 혼란 여부는 실사용자 검증 필요)
- **발생 가능성**: `[추론]` 중간
- **영향받는 다른 페르소나**: 없음(이 페르소나에 특히 민감)
- **개선 방향**: 하단/상단 내비게이션에 아이콘+텍스트 병기 검토.
- **실제 사용자 검증 필요 여부**: 예 — 중장년 사용자의 실제 탭 인식 성공률 측정 필요.

### 문제 2: "도감" 등 게임화 용어가 기능을 직관적으로 설명하지 못함
- **페르소나**: 7
- **발생 위치**: 상단 네비게이션 "도감" 탭
- **증거 유형**: `[실행 확인]`(용어 확인) + `[추론]`(이해도 저하 여부)
- **실제로 발생한 일**: "도감"은 컬렉션/가챠 카드 보관함을 의미하는 게임 용어. 학습 앱 맥락에서 처음 보면 기능을 유추하기 어려울 수 있음.
- **문제가 되는 이유**: 이 페르소나는 게임 경험이 적을 가능성이 높아, "도감이 뭐지?"라는 의문에서 탐색이 멈출 수 있음.
- **심각도**: `[추론]` S3 보통
- **개선 방향**: 툴팁이나 부제 병기 검토.
- **실제 사용자 검증 필요 여부**: 예.

### 문제 3: 오디오 재생 자체의 신뢰성 미검증
- **페르소나**: 7 (1과 공통)
- **증거 유형**: `[실사용자 검증 필요]`
- **실제로 발생한 일**: 이 테스트 환경에서는 브라우저 TTS(Web Speech API) 또는 사전 생성 mp3가 실제로 음성을 재생하는지 청취로 확인할 수 없었음. 코드상 mp3 우선, 실패 시 Web Speech 폴백 로직은 확인함(`[코드 확인]`, `src/tts.ts:123-171`).
- **문제가 되는 이유**: 중장년 사용자에게 음성 재생은 핵심 기능인데, 실기기·실브라우저 환경(특히 구형 기기, 음소거 모드, 권한 문제)에서의 실제 재생 안정성은 코드 리딩만으로 보장할 수 없음.
- **실제 사용자 검증 필요 여부**: 예 (필수).

## 7. 학습 콘텐츠 적합성
- `[추론]` 카드당 정보량 자체는 페르소나 1 테스트에서 확인한 바와 같이 과도하지 않음(강점 공유).

## 8. 화면 및 조작 적합성
- `[실행 확인]` 모바일 375px에서 레이아웃 자체는 깨지지 않고 세로 스크롤로 잘 반응함(카드형 UI가 폭에 맞춰 축소). 다만 버튼 탭 영역 크기나 폰트 크기가 저시력 사용자에게 충분한지는 정밀 측정하지 않음 `[실사용자 검증 필요]`.
- `[실행 확인]` 다크 테마 기본이며 대비가 나쁘지 않아 보이나 정량적 명도대비 측정은 하지 않음.

## 9. 여행 현장 활용 가능성
- `[코드+실행 확인]` 공통 구조적 문제(F1/F3)의 영향을 동일하게 받아, 미리 충분히 학습해두지 않았다면 현장에서 원하는 문장을 찾기 어려움.

## 10. 실제 사용자에게 검증해야 할 가설
- 중장년 사용자의 실제 탭 라벨 인식률(아이콘 없는 텍스트 탭 vs 텍스트 없는 아이콘 버튼).
- 실기기에서 음성 재생 성공률.
- "이어하기" 재개 방식의 실제 사용 편의성.

## 12. 이 페르소나에게 앱을 추천할 수 있는가
**조건부 가능 — 실사용자 검증 필수.** 온보딩 절차 자체는 단순하나(회원가입 없음, 건너뛰기 가능), 내비게이션 라벨링 방식(아이콘/텍스트 비일관)과 음성 재생 안정성처럼 이 페르소나에게 결정적인 요소들이 코드 분석만으로는 확정할 수 없어, 실제 중장년 사용자 대상 검증 전에는 추천 여부를 단정하기 어렵다.
