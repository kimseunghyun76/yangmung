## 문제 2 후속 갱신 (1차: S2 "D-day/카운트다운 입력 기능 자체가 없음") → 해결
- **판정**: **해결**. `[실행 확인]` 설정 화면에 "출국일" 섹션(네이티브 날짜 입력 + 지우기 버튼) 신규 추가, 홈 화면에 "🗓 출국 D-N" 배지 표시. 실제로 2026-08-07을 입력해 홈 화면에 "출국 D-12"가 정확히 뜨는 것을 확인.
- **범위 한계**: 계획대로 입력·표시만 구현했고, 커리큘럼 압축/카테고리 우선순위 알고리즘(문제 2, 카테고리 지정 무작위 오픈)은 이번에도 포함하지 않음 — 이는 "5일 안에 필요한 것만"이라는 근본 니즈의 절반(급박함 인지)만 해결한 것.
- `npm run typecheck` 통과 확인.

## 재검증 결과

### 문제 1 (1차: S2 "여행 스타일 배너가 커리큘럼에 영향을 주지 않음 — 기대와 실제 불일치") → 완화
- **판정**: **완화**. `[실행 확인]` 홈 화면 배너 문구를 "고르면 그 일정에 맞는 팁을 챙겨드려요"에서 "고르면 일정에 맞는 문화·여행 팁을 보여드려요(**학습 순서·미션 구성은 그대로예요**)"로 변경한 것을 실제 화면에서 확인. 실제 동작(팁 필터링만)은 1차와 동일하지만, 문구가 그 사실을 정직하게 미리 알려 "커리큘럼이 바뀔 것"이라는 오해 자체를 예방함.
- **한계**: 기능이 추가된 게 아니라 기대치 조정이므로, "5일 안에 필요한 것만 빠르게"라는 이 페르소나의 근본 니즈(카테고리 선택 학습, D-day 반영)는 여전히 미해결. 1차 문제 2(카테고리 지정 불가)·3(D-day 부재)은 이번 범위에 포함되지 않아 그대로 유효.
- **심각도 변화**: S2(기대-실제 불일치) → S3(기능 부재 자체는 남지만 오해는 줄어듦).

### 신규 확인: 긴급 상황 표현만큼은 벼락치기 사용자도 즉시 확보 가능
- `[실행 확인]` 이 페르소나가 "여행 당일 필요한 문장"으로 안전/응급 표현을 원한다면, 이제 "긴급" 화면을 통해 5일이 아니라 즉시 확보 가능해졌다(persona-05 재검증 결과와 동일 메커니즘). 다만 이 페르소나가 원래 우선순위로 꼽은 식당·교통·호텔은 여전히 무작위 오픈 구조 그대로.
