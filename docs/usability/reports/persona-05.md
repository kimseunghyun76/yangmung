## 1. 페르소나 요약

## 2. 테스트 환경
- `[실행 확인]` 신규 사용자 → 설정에서 "중급"으로 직접 전환 → 미션 지도 실제 진입까지 확인.
- `[코드 확인]` 전체 미션의 tier(난이도 단계) 배정표(`src/content/missions/index.ts:41-49`)와 잠금 로직(`src/views/Map.tsx`)을 직접 확인.

## 3. 수행한 과업
1. 아이를 잃어버린 상황 찾기
2. 노인이 넘어져 다친 상황 찾기
3. 알레르기 설명하기
4. 복용 중인 약 설명하기
5. 병원 접수 및 긴급전화 정보 찾기

**모든 과업에 대해 "20초 이내 접근 가능한가"를 기준으로 평가.**

없음. 5개 과업 중 신규 사용자 기준으로 20초는커녕 첫 세션 안에 도달 가능한 과업이 하나도 확인되지 않음.

## 5. 실패하거나 중단된 과업 — 근본 원인 분석

### 핵심 발견: 안전·응급 콘텐츠가 전부 최고 난이도(tier 5)에 배치되어 있고, tier 진입 자체도 무작위 순차 오픈 방식
- `[코드 확인]` `src/content/missions/index.ts:41-49`의 tier 배정표를 직접 확인한 결과:

| 상황 | 미션ID | tier | 코드 내 분류 주석 |
|---|---|---|---|
| 미아 찾기 | C53 | **5** | "위기 대응: 재검수에서 확인된 공백 보강" |
| 지진·재난 대응 | C51 | **5** | 위기 대응 |
| 병원 접수 | C52 | **5** | 위기 대응 |
| 병원에서 증상 설명 | C25 | 4 | "트러블·교섭" |
| 분실물과 길 도움 요청 | C26 | 4 | 트러블·교섭 |
| 긴급상황에서 도움 청하기 | C27 | 4 | 트러블·교섭 |
| 약국에서 약 사기(알레르기 문구 포함) | C6 | 2 | 생활 확장 |

- `[실행+코드 확인]` 미션 잠금 자체가 이중 구조다: ① `missionsLocked`(입문·기본 레벨)이면 미션 탭 전체가 안 보임(F1) → 최소 "중급" 승급 필요. ② 중급으로 승급해도 53개 장면 중 **딱 1개**만 열려 있고 나머지는 "학습할수록 무작위로" 열림(`Map.tsx:36-39`, 직접 확인). 특정 미션을 지정해서 열 방법이 전혀 없다(F3).
- 따라서 **가장 위중한 3개 콘텐츠(미아·지진·병원접수)는 tier 5로, 이론상 tier 1~4의 40개 미션을 무작위로 먼저 통과해야 등장 확률이 생기는 위치**에 있다. "20초 이내 접근"은 커녕, 신규 사용자 기준 여러 날의 학습 없이는 도달 자체가 불가능한 구조다.

## 6. 발견한 문제

### 문제 1 (전체 테스트 최고 심각도): 응급 안전 콘텐츠에 즉시 접근할 방법이 전혀 없음
- **페르소나**: 5 (1, 4, 6에도 파생 영향)
- **발생 위치**: `src/content/missions/index.ts:41-49`(tier 배정), `src/views/Map.tsx:36-39`(무작위 오픈), 앱 전체에 "응급" 진입점(버튼/메뉴) 부재
- **수행하려던 과업**: 미아·부상·알레르기·응급 상황 대응 표현 찾기
- **증거 유형**: `[코드 확인]` + `[실행 확인]`(미션 잠금·무작위 오픈 동작 자체는 직접 조작하여 확인)
- **실제로 발생한 일**: 응급 콘텐츠가 최고 난이도에 배치되어 있고, 전용 진입 메뉴("긴급" 아이콘/바로가기 등)가 홈·네비게이션 어디에도 없다. 검색(복습>표현/장면별)도 "이미 학습한 것"만 대상이라 무용지물이다(F3와 동일 근본 원인).
- **사용자가 기대할 행동**: 여행 중 실제 응급 상황(아이를 놓침, 부모님이 넘어짐)이 발생하면 앱을 켜자마자 "응급" 메뉴를 눌러 10초 안에 필요한 문장이나 화면을 상대에게 보여줄 수 있길 기대함.
- **문제가 되는 이유**: 이 앱의 PRD/README가 명시하는 "얼어붙지 않게"라는 핵심 약속과 정면으로 배치된다. 정작 가장 얼어붙기 쉬운 순간(아이를 잃어버렸을 때)에 앱이 아무 도움이 안 될 가능성이 매우 높다.
- **재현 단계**: 신규 계정 → 설정에서 "중급" 전환(또는 정상적으로 승급) → 미션 지도 진입 → 열린 장면 1/53 확인 → C51/52/53에 직접 접근할 UI가 없음을 확인.
- **심각도**: **S0 차단** (안전이 핵심 목적인 사용자군에게는 주요 과업을 완료할 수 없는 수준)
- **발생 가능성**: 높음 (이 페르소나의 전형적 시나리오)
- **영향받는 다른 페르소나**: 1(완전 초보라 더더욱 도달 못함), 4, 6(장기체류 중 응급 발생 가능성)
- **개선 방향**: (제안만) 응급 콘텐츠는 tier·잠금 시스템과 별개로 항상 접근 가능한 "긴급 모드" 또는 홈 화면 고정 진입점을 마련하는 방안을 최우선 검토 대상으로 제안.
- **실제 사용자 검증 필요 여부**: 이 발견 자체는 코드·조작으로 충분히 확정적이나, "실제 응급 상황에서 사용자가 이 앱을 열 생각조차 할지"는 `[실사용자 검증 필요]`.

### 문제 2: 개발자 전용 우회 수단이 유일한 탈출구이나 일반 사용자 대상이 아님
- **페르소나**: 5
- **발생 위치**: 설정 > 🛠 개발자 도구 > 접근 제한 해제 (`src/views/SettingsModal.tsx:168-174`)
- **증거 유형**: `[코드 확인]`
- **실제로 발생한 일**: 이 토글을 켜면 모든 장면 잠금이 해제되나, "테스트용"이라 명시되어 있고 프로덕션 빌드에도 그대로 노출된다(env 가드 없음, `[코드 확인]`).
- **문제가 되는 이유**: 일반 사용자, 특히 이 페르소나(디지털 능숙도가 반드시 높지 않을 수 있는 보호자)가 이 옵션의 존재나 의미를 알아채고 사용할 것이라 기대하기 어렵다. 안전장치를 개발자 도구 뒤에 숨겨두는 것은 근본 해결책이 아니다.
- **심각도**: S3 보통 (해결책이 아니라 부수적 관찰)
- **개선 방향**: 문제 1의 해결책이 마련되면 자연히 불필요해짐.
- **실제 사용자 검증 필요 여부**: 아니오(코드로 충분히 확정적).

### 문제 3: 긴급전화번호 등 정적 참고 정보 부재
- **페르소나**: 5
- **증거 유형**: `[코드 확인]`
- **실제로 발생한 일**: 119/110 같은 일본 긴급 연락처 요약 정보가 콘텐츠에 없음.
- **문제가 되는 이유**: 학습형 콘텐츠(대화 카드)만으로는 부족하고, 위기 상황에서는 암기 없이 바로 보여줄 수 있는 "치트시트"형 정보도 필요함.
- **심각도**: S2 중요
- **개선 방향**: 응급 연락처 요약 카드 추가 검토.
- **실제 사용자 검증 필요 여부**: 예.

- `[실행 확인]` 미션 잠금/오픈 UI 자체는 명확하게 "잠김"과 "몇 % 남음"을 보여줘 혼란은 없으나, 바로 그 명확함이 "이 콘텐츠에 못 간다"는 사실을 더 분명하게 보여줌.

## 9. 여행 현장 활용 가능성
- **매우 낮음.** 응급 상황은 예고 없이 발생하는데, 사전에 해당 미션을 "무작위로" 미리 열어두지 않았다면 현장에서 즉시 대응 불가.

## 10. 실제 사용자에게 검증해야 할 가설
- 실제 보호자가 여행 전 "혹시 몰라서" 응급 미션이 열릴 때까지 미리 그라인딩하는 행동을 보이는지, 아니면 애초에 이 앱을 응급 목적으로 신뢰하지 않게 되는지.
- 응급 연락처 카드가 추가된다면 실제 재난 상황 시뮬레이션에서 도움이 되는지.

## 12. 이 페르소나에게 앱을 추천할 수 있는가
**현재 구조로는 권할 수 없음.** 이 앱은 관광·생활 회화 학습 도구로서는 충실하나, "안전을 최우선으로 하는 가족 동반 여행자"의 실제 니즈(응급 시 즉시 접근)에는 구조적으로 응답하지 못한다. 콘텐츠 자체(미아·지진·병원)는 만들어져 있으므로, 접근 경로만 별도로 마련되면 이 페르소나에게도 유효한 도구가 될 잠재력은 충분하다.
